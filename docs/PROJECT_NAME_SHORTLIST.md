# Project Name Shortlist — Sprint 2 Vote

**Purpose:** finalise the project name before Sprint 2 UI and documentation
work begins. Vote to be held at the start of Sprint 2.

## What we're naming

> A rule-based learning-resource recommendation engine that suggests study
> materials (videos, articles, exercises) based on predefined rules.

## Candidates (from Aarjan's initial list)

| Name       | Notes                                                 |
| ---------- | ----------------------------------------------------- |
| LearnPath  | Suggests a guided journey through resources           |
| PathFinder | Similar direction, slightly more generic              |
| Sensei     | Playful, implies guidance/expertise                   |
| EduMatch   | Emphasises the "matching" mechanic of the rule engine |
| Lernly     | Short, brandable, modern SaaS-style name              |
| LogicLearn | Nods to the rule-based logic under the hood           |
| StudyBuddy | Friendly, approachable, student-facing                |

## Recommended shortlist

### 1. EduMatch — recommended first choice

EduMatch most clearly communicates the product's core value: matching learners
with relevant educational resources. It is concise, memorable, user-focused,
and broad enough to support videos, articles, exercises, and future
recommendation features.

### 2. LearnPath — strong alternative

LearnPath suggests a guided learning journey and is easy for users to
understand. It is a good choice if the project emphasises progression and
structured learning rather than matching alone.

### 3. StudyBuddy — approachable alternative

StudyBuddy feels friendly, accessible, and student-focused. It may appeal to
users who want supportive guidance, although it is less distinctive than
EduMatch.

## Names to deprioritise

The following four names should remain available for discussion but are
recommended as lower-priority options:

- **PathFinder** — Somewhat generic and potentially associated with navigation,
  travel, or unrelated search products. It communicates direction but not the
  educational-resource matching purpose as clearly as EduMatch or LearnPath.
- **Sensei** — Memorable and playful, but it suggests a human tutor, teacher,
  or instructor rather than a rule-based recommendation engine. It may also
  create expectations about personalised teaching that the current product
  does not provide.
- **Lernly** — Short and brandable, but its purpose is not immediately obvious
  to new users. The unusual spelling may also require explanation and make the
  educational focus less clear.
- **LogicLearn** — Accurately reflects the rule-based implementation, but it
  sounds more technical and developer-oriented. It may focus attention on the
  underlying logic instead of the user's benefit: finding suitable learning
  resources.

## Voting process

1. Shortlist finalised in team channel before Sprint 2 kickoff.
2. Each member casts one vote.
3. Tie-break: Frontend Lead (Astraea) and Data/Model Lead (Nishant) decide
   jointly, since the name affects both UI branding and documentation.
4. Winning name gets updated across: root `README.md`, `frontend/README.md`,
   `backend/README.md`, Vercel project name/description, and any UI landing
   text.
